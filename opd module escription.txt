Here’s a useful handoff brief for another agent planning an IPD module over this OPD app.

**App Description**

This is a multi-clinic OPD management system for Indian clinics. It is built around patient registration, appointments, doctor visits, EMR/prescriptions, billing, pharmacy, reports, WhatsApp communication, AI-assisted OCR/NLP, LIMS/HIMS lab order integration, ABDM/ABHA fields, and clinic analytics.

The app is clinic-tenant based: most core records have `clinic_id`, and frontend services first resolve the current user’s `Profile` and `clinicId` before reading/writing data. The existing design should be extended, not bypassed, for IPD.

**Tech Stack**

- Frontend: React 18 + TypeScript + Vite
- Styling/UI: Tailwind CSS, lucide-react icons
- Routing: `react-router-dom`
- Backend/database: Supabase Postgres
- Auth: Supabase Auth with `profiles`, `roles`, `permissions`, `clinic_settings`
- Server functions: Supabase Edge Functions under `supabase/functions`
- Netlify Functions: WhatsApp proxy/backend calls under `netlify/functions`
- Mobile/PWA: Capacitor + Vite PWA
- AI: Google Vision OCR, Gemini NLP, medical text/image analysis
- PDFs: frontend PDF generation plus Supabase function `generate-pdf-from-html`

**Current Data Model**

Core existing tables from `database_schema.md`:

- `clinic_settings`: tenant/clinic config, fees, PDF settings, WhatsApp settings, clinic tier
- `profiles`: users/staff/doctors, role, permissions, clinic assignment
- `roles`: role names and permissions
- `patients`: demographics, phone, ABHA fields, soft hide
- `appointments`: OPD appointment scheduling/status
- `visits`: OPD encounter/EMR root record
- `symptoms`, `diagnoses`, `prescriptions`, `tests_ordered`, `test_results`: visit-linked clinical data
- `bills`, `bill_items`, `payment_records`, `refund_requests`: billing and collection
- `medicines_master`, `pharmacy_inward_*`, `pharmacy_dispensed_items`, `stock_movement_log`: pharmacy/inventory
- `hims_lab_orders`, `lims_outbound_orders`: lab integration
- `whatsapp_message_queue`, `whatsapp_message_log`, `whatsapp_auto_send_rules`, `whatsapp_message_templates`: messaging automation
- `abdm_audit_log`: ABDM audit trail
- `ocr_uploads`, `ocr_results`, `voice_transcripts`: AI/EMR capture support

**Integration Rules**

Use existing `patients` table. Do not create separate IPD patients.

Use existing `profiles` for doctors, nurses, reception, admin. Add role/permission checks only if needed.

Use existing `bills`, `bill_items`, and `payment_records` for IPD billing. Add `admission_id` to `bills` or create an `ipd_bill_links` table if avoiding migration risk. Bill item types should support room rent, nursing charge, procedure, pharmacy, lab, consultation, package, discount, deposit/advance.

Use existing pharmacy stock deduction for IPD medication administration/dispensing. IPD medicine usage should update `pharmacy_dispensed_items` or a parallel IPD medication issue table that also writes stock movements.

Use existing `tests_ordered`/`test_results` if possible, but they currently require `visit_id`. For IPD, either allow `admission_id` on lab orders or create an IPD-linked order wrapper.

Use existing PDF infrastructure for discharge summary, IPD bill, consent forms, and admission sheet.

Use existing WhatsApp queue/templates for admission confirmation, daily estimate, discharge summary, payment reminders, and follow-up after discharge.

Use existing analytics function pattern for IPD dashboard metrics.

**Security/RLS Pattern**

Every new IPD table should include `clinic_id` and RLS like the existing pattern:

```sql
clinic_id IN (
  SELECT clinic_id FROM profiles WHERE id = auth.uid()
)
```

Also add indexes on:

```txt
clinic_id
patient_id
admission_id
status
created_at/admission_date
current_bed_id
```
